# QuizMind AI 架构与验收原则

## 产品边界

QuizMind AI 是一个网页版答题入口：用户粘贴一道或多道题，系统返回答案、选项内容、解析和可追溯证据。它不是静态答案表，也不把大模型的自信语气当成正确性证明。

## 总体数据流

~~~mermaid
flowchart TD
  A["粘贴题目"] --> B["题目拆分与题型识别"]
  B --> C{"已审核题库精确命中？"}
  C -->|是| D["选项文本对齐与答案映射"]
  C -->|否| E["知识库检索"]
  E --> F{"证据是否充分？"}
  F -->|是| G["逐选项判断与交叉核验"]
  F -->|否| H["实时权威来源检索"]
  H --> I{"仍有充分证据？"}
  I -->|是| G
  I -->|否| J["拒绝猜测 / 标记不确定"]
  D --> K["答案 + 解析 + 来源"]
  G --> K
  J --> K
~~~

## 五类核心数据

1. **原始资料**：官方 PDF、官方平台页面、官方数据库指南、公开培训材料。
2. **知识条目**：概念、操作路径、平台功能、适用条件、时间敏感事实。
3. **候选题目**：从资料中抽取的题干、选项、候选答案和解析，默认状态为 pending。
4. **审核题库**：经来源核验的题目，只有 verified 才能被 V0.1 本地答题器直接作为标准答案。
5. **证据记录**：来源 ID、标题、URL、发布日期/修订版、访问日期、页码或段落、原文证据片段。

## 答题路由

- **L1 精确匹配**：题干完全匹配，且选项文本可对齐；优先返回已审核答案。
- **L2 语义检索**：处理改写题、同义表达和选项顺序变化；低于阈值或候选接近时标记歧义。
- **L3 知识检索**：从官方命题范围和经过整理的资料中找证据，逐个判断选项。
- **L4 实时查证**：仅用于会变化的网页功能、平台入口、数据库页面和最新政策；必须保存访问时间。
- **拒答**：没有充分证据时返回“不确定”，不得用语言模型记忆补造来源。

## 多选题约束

多选题采用完整集合判定。系统要逐项记录“支持 / 反对 / 证据不足”，最后比较完整答案集合；不能因为找到一个正确选项就推断整道多选题正确。选项顺序变化时，先按选项文本映射，再生成用户当前题面的字母。

## 来源等级

- **A**：赛事主办方及官方平台原始资料，可作为最终答案依据。
- **B**：高校图书馆等学校官方通知及附件，用于交叉核验、定位主办方资料。
- **C**：第三方转录、博客、社区讨论，只作为检索线索，不能单独支撑标准答案。

对数据库或产品界面题，网页缓存和旧截图不等于当前功能状态；必须记录实际访问日期。资料版本不明确时，答案必须带版本警告。

## 部署建议

- 前端：静态网页，可部署在 GitHub Pages 或 Cloudflare Pages。
- 答题 API：独立服务端，保存模型与搜索服务密钥。
- 模型适配：使用 OpenAI-compatible API 抽象，模型供应商可替换。
- 搜索适配：服务端搜索接口 + 官方域名优先策略。
- 安全：浏览器端不得保存模型 API Key；限制请求体大小、频率和允许访问的来源域名。

## 验收指标

| 指标 | 验收方法 |
|---|---|
| 原题准确率 | 留出集逐题精确匹配 |
| 改写题准确率 | 同义改写、语序变化、干扰文本测试 |
| 多选集合准确率 | 必须完整集合完全一致 |
| 选项乱序映射准确率 | 随机重排 A-D 后核对 |
| 证据覆盖率 | 每个最终答案均有可打开的来源证据 |
| 拒答质量 | 无证据问题不得输出伪确定答案 |
| 实时题正确率 | 动态页面题按访问时间复核 |
| 响应延迟 | 分别统计题库命中与在线研究路径 |

## 当前实现边界

V0.1 已完成静态答题台、本地 JSON 题库导入、相似题匹配、选项内容映射、来源登记和 50 模块目录。内置审核题库为空；PDF 自动抽取、知识库检索、实时查证和服务端模型接口尚未接入。
